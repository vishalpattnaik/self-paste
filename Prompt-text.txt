@workspace We need to revert the previous split-logic and enforce a strict "Direct Dependencies Only" rule across the entire scanner. My team has decided that we must NEVER auto-bump or rewrite transitive dependencies, as local overrides cause conflicts with our core enterprise parent POMs.

Please refactor the filtering logic for ALL vulnerabilities (both Auto-Bump and OpenRewrite) to follow this single, strict rule:
1. Parse the target project's local `pom.xml`.
2. Check if the vulnerable dependency is explicitly declared inside the local `<dependencies>` block.
3. If the dependency is NOT physically written in the local `pom.xml` (meaning it is a transitive dependency inherited from a parent or another library), ignore it completely. 
4. Flag it as "SKIPPED: Transitive dependency - must be resolved via parent/core framework" and push it directly to the manual review report.
5. Only execute an Auto-Bump or an OpenRewrite recipe if the dependency is a DIRECT dependency explicitly present in the existing `pom.xml`.
