We need to fix the CVE filtering logic. The previous rule was too aggressive and accidentally blocked the auto-bump feature for standalone transitive dependencies (like log4j or postgresql). 

Please decouple the filtering logic into two distinct execution paths:

1. FOR AUTO-BUMP (Standalone CVEs with NO OpenRewrite recipe): 
Revert to the original behavior. The system MUST allow auto-bumping of transitives and dependencies inherited from the parent. (The tool should force the fix by injecting the patched version into the local `<dependencyManagement>` block or `<properties>` block).

2. FOR OPENREWRITE (CVEs that DO match a CSV recipe): 
Apply the strict safety filter ONLY here. Before adding a recipe to the execution queue, check if the vulnerable dependency triggering it is a deep transitive. If the dependency is purely transitive (not explicitly declared as a direct dependency in the pom.xml), DO NOT run the OpenRewrite recipe. Mark the recipe as skipped.

This ensures standalone transitives get patched locally, while protecting the build from massive framework rewrites triggered by hidden transitives.
